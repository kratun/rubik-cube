## Findings

Each finding: source, disposition (fix now / defer / accept).

### Aggregate views

1. **Size growth is in the tests, not the code.** Largest files at HEAD: `web/src/features/cube/CubePage.test.tsx` 595 lines, `hooks/useCubeSession.test.ts` 567, `components/SessionControls.test.tsx` 223; the largest production file is `hooks/useCubeSession.ts` at 187 lines, `CubePage.tsx` 69. No god class. The two big test files hold repeated session set-up helpers (`readySession`, `readyMovedSession` defined inside several `describe` blocks of `useCubeSession.test.ts`). *Disposition:* defer, decide at 4.2 whether it is "unwieldy" under the CLAUDE.md test rule (move helpers to a shared file, do not add a second test class). *Prevention:* none needed yet.
2. **Architecture delta.** The frontend layering rules (`no-restricted-imports` in `web/eslint.config.js`) were added in the unplanned refactor PR #32 (`ef77ffc`, `d6bd04d`, `c338fe1`, `bfaf513`) between 3.4 and 3.5; `npx eslint .` passes at HEAD. One new cross-folder edge in 3.6: `app/ErrorBoundary.tsx` imports `features/cube/components/AlertBanner.tsx`; the rules allow `app` to import features, so it is an accepted dependency, not a violation. No cycle found by reading the imports (not tool-checked). *Disposition:* accept.
3. **Duplication map.** No duplicated logic found across stories: one move-token table (`utils/moves.ts`, `MOVE_TOKENS` derived from `MOVE_TOKENS_BY_FACE` in 3.6), one mutation path in the hook (`mutate` in `useCubeSession.ts`), one fetch wrapper (`services/client.ts`), one alert banner (`AlertBanner.tsx`). *Disposition:* accept (this is the DRY rule working).
4. **Pattern divergence: magic values.** 3.6's first test pass used bare `"true"`/`"false"` attribute values; they were replaced with named constants in the same story. CSS literals (breakpoint `60rem`, `999px`, `clamp(...)`) are not covered by the CLAUDE.md wording, which names code and tests. *Disposition:* accept; propose a one-line clarification (action item 7).
5. **Pattern divergence: line endings.** `npm run lint` warns on CRLF files at HEAD (`.prettierrc.json`, `e2e/ttc.spec.ts`, `eslint.config.js`, `index.html`, ...): `core.autocrlf=true` here and Prettier's default is LF, while the Epic 1 `.gitattributes` item landed. Source: `npm run lint` output in this retro; `web/package.json` script `lint`. *Disposition:* fix at 4.2 (action item 1). *Prevention:* CI (Story 5.3) would check out LF, so it will not catch it; a local fix is needed.
6. **Spec-to-implementation reconciliation (3.6).** The frozen Intent of `spec-3-6-...md` did not mention the exploded-view modal, the Session-above-Moves order or the flat history chips; the owner asked for them after the first implementation, over four rounds. As built: `epics.md` Story 3.6, 3.2 and 3.5 criteria and the README run section were updated in commit `56df425`; the spec's Implementation Notes record the decisions. *Disposition:* accept (reconciled). *Prevention:* action item 6.
7. **Repeated rejected finding became a story.** "No busy state while a request runs" was rejected in the 3.3, 3.4 and 3.5 triage logs ("same decision as 3.3 and 3.4") and became Story 3.6. The three rejections were each correct for their story; together they were a signal. *Disposition:* accept; lesson in action item 6.

### Review lenses (story boundaries)

8. **Verification gap (resolved): `dotnet test` showed "Zero tests ran" in this retro's environment only.** `dotnet test` at the repository root and per project (`global.json` selects `Microsoft.Testing.Platform`, tests are xunit.v3) reported exit code 5 with zero tests for all four test projects, while the built hosts run directly pass: Domain 186, Application 48, Infrastructure 8, Api 92 (334 tests, 0 failed). The owner ran `dotnet test` on their terminal: all four projects discovered and passed, 334 total, 0 failed, 13 s. So the cause was this retro's sandbox, not the project, and the README command works. *Disposition:* accept (action item 4 closed).
9. **Test coverage of the end-to-end path.** `web/e2e/ttc.spec.ts` is the only e2e test (the TTC flow, now with the exploded-view dialog). 3.5 triage already accepted that only the solved-cube path is covered. *Disposition:* accept.
10. **Stale epic context.** `epic-3-context.md` was compiled before 3.6 (it lists six stories but knows neither the modal nor the Session layout); `epics.md` is now newer, so `bmad-build` recompiles it on the next epic-3 story. *Disposition:* accept.

### Deferred work state

Story 4.2 is the heaviest remaining story; consider whether its scope needs splitting.
