# Epic 3 Context: Interactive web interface

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

A reviewer sees the cube as coloured tiles and as text, turns it by buttons and keys, reviews the history, undoes, resets, and runs the TTC Test Sequence in one click. The UI holds no cube logic: the server is the source of truth.

## Stories

- Story 3.1: Frontend scaffold with generated API types and a typed client
- Story 3.2: Show the cube and keep the session in the URL (FR8)
- Story 3.3: Apply moves by buttons and keyboard (FR9)
- Story 3.4: Move history, undo and reset (FR11)
- Story 3.5: TTC Test Sequence in one click and the end-to-end check (FR10, NFR3)

## Requirements & Constraints

- Tiles and text view render `faces` and `explodedView` from the API unchanged; the frontend never recomputes layout or colours.
- Every tile exposes its colour name to assistive technology; controls are real buttons, keyboard operable; queries in tests are by role.
- Keys `F R U B L D` send the clockwise token, `f r u b l d` the counter-clockwise one; keys with Ctrl, Alt or Meta are ignored.
- 400/500 show the message and keep the last good state; 409 reloads the session and says it was changed by someone else; a network failure shows a clear error and the page stays usable.
- TypeScript strict, ESLint, Prettier, no `any`; tests beside the file; no magic values.

## Technical Decisions

- Same-origin: the client calls relative `/api/...` paths only. Vite (port 5173) proxies `/api` to the API on 5080; non-`/api` paths such as `/cubes/<id>` fall back to `index.html`.
- Types are generated by openapi-typescript from the Development swagger document into `web/src/services/types/generated/` (committed, one npm script). `ApiResult<T>` and the fetch wrapper are hand-written.
- State lives in one `useCubeSession` hook (`useReducer` plus the fetch wrapper); the `cubeId` is in the URL; every mutation sends the last seen `revision`.
- Layout: `web/src/services` (client and `types/`), `web/src/features/cube` (`components/`, `hooks/`, `utils/`, `testing/`), `web/src/app`; import rules in the architecture spine.

## Cross-Story Dependencies

- 3.1 provides the typed client and tooling that 3.2 to 3.5 build on.
- 3.2 introduces the session hook and URL routing; 3.3 and 3.4 extend it; 3.5 adds the e2e flow and README run section.
